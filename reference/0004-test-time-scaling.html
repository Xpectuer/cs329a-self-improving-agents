测试时计算扩展速查卡

第 3 课配套参考 · 后续课程会反复回看 · 打印友好

不训模型的情况下，怎么把推理时的算力变成质量：指标怎么读、规律怎么看、受限提交时怎么选。

1. 四个关键指标

指标含义衡量什么
pass@k生成 k 个样本、全部提交生成/覆盖上限（搜索能力）
10@k生成 k 个、只交 10 个生成 + 筛选/聚类能力（贴近真实约束）
best-of-n验证器给 n 个候选打分选最优验证器质量 × 采样规模
自洽性（SC）多数投票（思维链采样后取众数）不依赖验证器的兜底策略

2. 两条扩展规律

有验证器：求解率随采样预算对数线性增长（Large Language Monkeys）——模型越大斜率越陡。

无可靠验证器：多数投票在采样 10~50 个后饱和——难题的正确解在千万样本中只出现一两次，被淹没。

数字锚点：1M 采样下 10@M ≈ 30% vs pass@M > 40%，差额就是筛选瓶颈（第 2 课）；10@k 从 10@1k 拉到 10@1M 持续提升；41B 一致优于 9B，41B+聚类又一致优于 41B。

3. 受限提交的选择器决策

场景主选理由
可验证领域（数学答案/单测）规则验证器 + 过滤可靠自动，直接筛掉错解
可验证但候选雷同+ 语义聚类多样化解替代重复提交，回补 10@k 损失
不可验证（文案/设计）RM / LLM-as-a-Judge 重排无 ground truth，只能学质量分数
无任何验证器多数投票（self-consistency）兜底；难点上会饱和

4. AlphaCode 流水线（受限提交范式的完整体）

题目 → 100 万候选采样（一半 Python 一半 C++，高温度 + 随机化标签/难度）
     → 样例测试过滤
     → 语义聚类（独立测试输入生成模型：预测输入 → 执行比对 → 语义等价归簇）
     → 挑 10 个提交 → Codeforces 测评

成绩：10 场竞赛平均排名 54.3，≈ 六个月内 28% 的参赛者水平（AI 首次端到端解决真实竞赛题）。wiki/alphacode

5. 何时该扩展、何时该停

  • 该扩展：有可信验证器 + 任务难但正确解在模型搜索空间内（覆盖尚未饱和）
  • 该停：多数投票已饱和且无验证器（加采样白烧算力）；小模型追大模型往往要指数级样本——考虑换训练侧
  • 注意：纯采样扩展不改行为——按第 1 课标准它不是演化（是 test-time compute scaling，见 框架速查卡 §2.1）
