验证器选型速查卡

第 2 课配套参考 · 后续课程会反复回看 · 打印友好

验证器是自进化闭环的枢纽：它决定测试时「选哪个」，也决定训练时「奖励什么」。这张卡帮你看清差距在哪、该用哪种验证器。

1. 生成-验证差距

定义：模型生成能力强、验证能力弱——当没有可靠验证器时，从大量候选里选出正确解远难于生成正确解。（wiki 页）

两条实证证据：

  • 多数投票采样到 10~50 个样本就饱和；完美验证器下的覆盖上限远高于它，难题（MATH vs GSM8K）差距更大
  • 10@k vs pass@k：1M 采样下，只准提交 10 个解的 10@M ≈ 30%，全部提交的 pass@M > 40%——筛选/聚类阶段就是瓶颈；聚类能显著回补 10@k

2. 验证器在闭环的两个位置

测试时：生成 → 验证器筛选 → 提交（best-of-n、10@k、聚类）
训练时：生成 → 验证器打分 → 奖励 → 更新权重（STaR、RLVR）

验证是连接测试时扩展与训练时扩展的桥梁（wiki 页）。同样的验证器，一个用来「选」，一个用来「教」。

4. Math-Shepherd：自动步骤标注

关键：不是回看，是重跑。标注对象是每条轨迹的每个中间步骤（包括最终算错的轨迹），做法是以该步骤为前缀重新生成 N 条完整解，用规则验证器（如数学答案）判定每条的最终对错。例：步骤 s₁「15+20=35」的 N=3 条续跑中 1 条最终做对 → 软估计 1/3，硬估计 1。训练 PRM：输入前缀，预测最终做对概率。

因此「最终答案正确 ≠ 每一步都对」——错步可能被后续采样救回（虚高分），对步也可能重跑全错（靠运气）。这正是自动标注噪声的来源（wiki 页）。

N 是数据构建超参数（不是训练优化超参数）：主实验用 completer（LLemma-7B）为每个步骤补全 N=8 条轨迹；消融实验显示 N=4 时硬估计标签准确率最高（86%），N 继续增大硬估计因假阳性反而下降，软估计则随 N 增大更贴合人工分布（但两者训出的 verifier 差异不大）。选硬估计是工程原因——可用标准 LM 管线（两个特殊 token 表「有潜力/无潜力」）。代价：补全计算随 N 线性增长（论文 Limitations）。无需人工标注即超越 SC/ORM/PRM800K；已知局限：难题信号不足、中间错误被后续掩盖、非常规路径被低估。arXiv:2312.08935 §4–5

5. 为什么可验证领域自进化最成熟

验证机制必须比生成任务本身更简单，才能在无需人工逐项检查的前提下大规模筛选正确样本。

数学（形式化证明）、编程（单元测试/执行反馈）、语言转换（输入输出等价性）都满足这一点——于是「生成 → 验证 → 筛选 → 更新」的闭环能可靠运转，训练时扩展因此在数学上特别有效（GPT-3.5 AIME ≈ 5% → DeepSeekMath-7B 通过训练时扩展达 51.7%+）。

依据：生成-验证差距、验证、可验证领域、过程奖励模型；课程第 3 讲 Robust Verification。
