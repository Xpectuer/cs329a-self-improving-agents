# 推理训练技术

> Source(s): raw/ch-05-总结：闭环自我改进与可验证领域

推理训练是提升大语言模型多步推理能力的关键环节，主要技术路径包括监督微调（SFT）与强化学习（RL）。在可验证领域（如数学、代码）中，RL 能够通过奖励信号驱动模型自我改进，但训练难度更高；SFT 则在高品质数据充足时更高效，但难以带来推理能力上的根本提升。实际应用中需要根据数据规模、基础设施和任务难度，在 STaR、DeepSeekMath + GRPO、DAPO 等方法中做出选择。

## SFT 与 RL 的取舍

在拥有强奖励信号的领域，RL 提供了用**更少样本**进行“爬山”（hill-climb）的能力，但整个训练过程需要大量调优工作。SFT 则相反：如果手头有大量高质量数据，它能更快地提升模型在特定任务上的表现，但**不会增强模型本身的推理能力**。

这一取舍决定了技术选型的方向：当资源有限、仅想快速获得一定推理能力时，SFT 或轻量 RL 方法更合适；当追求超越模型原始能力的推理水平时，则需要投入更多精力构建 RL 训练管线。

## RL 训练中的关键经验

实践中（如 DAPO/GRPO 在 AIME 上的实验）发现，单纯优化损失函数并不足以保证 RL 训练稳定有效。必须同步关注以下三个信号：

1. **响应长度（response length）**：模型会自然倾向于生成越来越长的推理链。过长且无用的输出会污染训练信号，需要引入 token 级损失或长度惩罚来控制。
2. **熵（entropy）**：生成熵不应过高或过低。熵过高表示输出发散，熵过低则探索不足；需要通过熵正则化或惩罚来维持平衡。
3. **全精度样本比例（percent of samples with full accuracy = 1）**：该比例决定了所需采样的数量，也是判断奖励信号是否饱和的重要指标。

在具体实现上，DAPO 通过一系列改进逐步提升了 Qwen-32B 在 AIME 上的表现：

| 技术 | 得分 |
|---|---|
| 初始 GRPO | 30 |
| + 过长过滤（overlong filtering） | 36 |
| + 非对称裁剪（asymmetric clipping） | 38 |
| + 软过长惩罚（soft overlong punishment） | 41 |
| + token 级损失（token-level loss） | 42 |
| + 动态采样（dynamic sampling） | 50 |

其中动态采样通过更均匀地分配批次中的奖励分布，实现了更好的信号传播，最终得分甚至超过了 DeepSeek-R1 蒸馏到 Qwen-32B 的效果。这说明即使在同一基座模型上，精细设计的 RL 算法也能独立实现强推理能力。

**训练稳定性风险**：当推理链变长，模型可能遭遇截断并产生大量噪声。可以通过增加 RL 循环中的上下文长度来缓解，也可以像 DAPO 那样引入逐步惩罚（gradual penalty）来稳定训练。若响应长度爆炸，需要控制损失；若多步训练后性能不再提升，则很可能奖励模型已经饱和。

## 技术选型指南

根据可用的数据量、计算资源和任务难度，可选择不同的推理训练技术：

### STaR —— 小规模、无 RL 基建

- **适用场景**：只有约 100 个带推理过程的示例，且没有强化学习基础设施。
- **特点**：实现简单，能让模型开始学会生成推理链。
- **效果**：在 GSM8K 等简单推理任务上能获得合理提升，但不会突破模型本身的能力上限。

### DeepSeekMath + GRPO —— 有限 GPU、标准数学推理

- **适用场景**：拥有较好的基础模型和指令数据，GPU 数量有限，但仍希望用 RL 强化推理。
- **特点**：GRPO 算法足够强，对内存和算力要求相对低，已在标准数学推理任务上得到充分验证。
- **前提**：需要一个足够好的基座模型，并用优质指令数据对模型进行预热（priming）。

### DAPO —— 长链推理、竞赛级难题

- **适用场景**：任务难度高，推理链很长（如 AIME、IMO 等竞赛级数学题），且追求最先进性能。
- **特点**：需要对 RL 算法和基础设施中的**所有变量**进行精细控制，包括长度惩罚、熵正则化、损失函数设计、采样策略等。
- **代价**：训练复杂度和调优成本最高。

## 共同收益与局限

三种技术通常都能带来以下改进：

- 大多数指标中的 **majority@K** 性能随计算量提升而增加；
- **答案格式**更加规范；
- 模型在**多步推理中的连贯性**更好。

但它们都无法实现：

- 提升模型的**根本能力**；
- 教会模型解决**全新类型的问题**；
- 在**领域外**进行广泛泛化。

因此，在可验证领域的闭环自我改进仍面临核心挑战：如何让模型超越既有认知边界，解决真正新颖的问题。这正是后续研究需要回答的问题。
