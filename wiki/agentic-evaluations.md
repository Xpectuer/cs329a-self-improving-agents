# Agentic Evaluations

> Source(s): raw/ch-01-引言：Agentic Evaluations 与 Long Horizon Tasks 概述, raw/ch-01-课程内容回顾, raw/ch-03-未来研究方向概览

## 概述

Agentic Evaluations（智能体评估）指对智能体在多步、长时程、真实世界任务上的表现进行评测。与传统的单轮问答或聊天基准相比，这类评估关注的不是“模型能否给出一个正确答案”，而是“模型能否在复杂环境中完成一个完整的、有实际价值的任务”。

课程引言提出了一个直接的问题：**你在自己的项目中用什么评估任务来评测 agentic evaluation？** 回答包括：

- multi-hop question answering 任务（例如 HotpotQA 一类）
- 基于私有 Wiki 的问答系统，将 Wiki 内容整理后输入给 coding agent
- 各类 knowledge task / body of knowledge task

这表明实践中的 agentic evaluation 形式多样，但共同点是它们都涉及多步骤的决策和交互。

## 课程脉络：从自改进到智能体评估

Agentic Evaluations 并非孤立出现，而是整门课程从“模型自改进”走向“真实世界工作流”的必然延伸。

课程的前半部分从 LLM 概述开始，重点介绍了 **test-time scaling** 和 **train-time scaling** 下的自我改进技术。其基本循环是：由 **verifier（验证器）** 驱动，模型从运行验证器获得的反馈中取得 reward，再通过强化学习甚至搜索算法，在数学、代码等任务上持续提升。

随后，课程进入 **进化策略（evolutionary strategies）** 与 **开放式探索（open-endedness）** 的讨论。此时不再仅仅用 reward 驱动自改进循环，而是允许模型在可定义的探索空间中自由探索，例如 alpha evolve 及相关技术。

接下来，课程转向 **基于工具使用的端到端智能体工作流**。模型通过与环境和工具交互，直接驱动端到端 workflow。如果任务需要在多个步骤中完成，智能体还需要访问知识库，因此引入了 **检索（retrieval）** 与 **记忆（memory）** 机制。随着工作流越来越接近真实世界，模型也需要更强的 **规划（planning）** 与 **多步推理（multi-step reasoning）** 能力。

正是在这一背景下，课程开始讨论：**如何在下一代模型中构建评估？哪些能力会驱动评估的发展？** 此外，多位客座讲者还覆盖了后训练（post-training）、多模态智能体、机器人与推理等主题。其中，符号化技术（symbolic techniques）也被归入工具使用的范畴，并与合成数据（synthetic data）这一趋势联系起来。

### 智能体作为 LLM 的推广

课程总结时再次强调：这门课关注的不只是 LLM，而是 agent。智能体是 LLM 的一种推广——它拥有目标，能够与环境交互、收集反馈，并利用反馈修正自己的步骤。它本质上是一个可以指挥自身流程、使用工具并最终达成目标的系统。

在当前范式下，LLM 本身往往还不足以独立驱动完整目标；因此许多系统仍以手写 workflow 的方式编排 LLM 与工具，例如同时编排 LLM、verifier、LLM-as-judge、工具调用、搜索算法乃至并行 LLM 调用。但在 coding agent 等场景中，已经可以看到由模型自行驱动的 agentic workflow。这意味着智能体必须有能力规划、在多步上进行推理、在走错方向时自我纠错，并持续提升自身能力——这正是 self-improvement 的核心。

### 未来研究重点

课程最后梳理了下一阶段的重要研究方向，并将其归纳为两个大主题：**自我改进的进一步突破**，以及**智能的效率（efficiency for intelligence）**。

- **跨领域泛化与推理链多样性**：test-time scaling 和 train-time scaling 目前仍较多局限于数学、代码等窄领域。未来需要让自我改进推广到更多领域，并让推理链足够多样化，从而持续驱动自我改进循环。
- **更强健的验证与元验证**：自我改进循环高度依赖 verifier；如何构建更 robust 的验证技术，或者对“进入推理链的信息”进行 meta verification，是极具价值的方向。
- **突破数据壁垒**：当前训练中使用的 prompt 往往是被静态选取、且需要人工挑选的。未来需要让自我改进循环能够自己选择合适的数据，从而打破数据瓶颈。
- **智能的效率**：关注“单位智能”的效率，即 intelligence per what aspects——用更少的计算、数据或交互获得更强智能。

## 与传统基准的对比

传统基准（chatbot 式对话、单轮问答、仅需从上下文中抽取信息的任务）正在快速饱和。过去四五年里，模型只要能生成解释就被视为重大突破；而现在，AI 进步的评价标准已经转向：

- 能否影响经济
- 能否影响安全
- 能否完成真实世界中人类可以完成的任务

因此，需要新的评估方式来衡量模型的 **能力（capability）** 和 **经济影响（economic impact）**。

## 评估的两个核心维度

课程指出，当前 agentic evaluations 主要回答两个问题：

1. **任务到底有多长、多复杂？**  
   衡量模型能完成的任务的时间跨度（time horizon）和复杂度。这要求评测任务从单步推理扩展到多步、长时程的规划与执行。

2. **任务的经济价值有多大？**  
   模型是否能够完成真实世界中有经济价值的任务，即替代或辅助人类专业工作。

### 长时程任务（Long-horizon tasks）

长时程任务是 agentic evaluations 的核心关注点之一，由其 **时间跨度（time horizon）** 和 **复杂度** 共同定义。随着传统单轮基准逐渐饱和，长时程任务成为衡量 AI 进展的关键方式，尤其是从能力提升和经济影响两个维度。

在课程中，学生分享的评估任务也体现了这一趋势：

- **Multi-hop question answering** 基准（如 HotpotQA）。
- **私有 Wiki 问答**：将内部 Wiki 整理成笔记后，输入给 coding agent 来回答问题。

这些任务从简单的单轮问答，转向更长、更具交互性的任务设定。

## 代表性基准

课程中提到的三个关键研究方向/基准：

### 1. 长时程任务测量

第一类工作聚焦于衡量模型能够完成的任务长度（time horizon）。这类评估不再只是“答对一道题”，而是看模型能否在多步操作、长期规划中保持一致性和正确性。

### 2. GDPVal（OpenAI）

GDPVal 是 OpenAI 发布的近期基准，用来衡量模型在 **真实世界、具有经济价值任务** 上的表现。这一方向回应了“模型能做真实专业人员所做的工作”的讨论，以非常实际的方式度量经济价值。

### 3. DeepScholar-Bench（Stanford）

DeepScholar-Bench 是一个 **实时（live）基准**，由斯坦福大学推出，专注于 **生成式研究综合（generative research synthesis）**。任务举例：给定一组论文，让模型撰写 related work（相关工作）章节。这类任务直接考察模型在深度研究型任务中的表现，例如对多篇文献进行综合、组织和写作。

## 实践中的评估场景

课程现场学生提到的实际评估案例包括：

- 私有 Wiki 问答：将公司内部文档整理成笔记，再输入给 coding agent 使用。
- Multi-hop 问答：需要模型在多个文档中进行多步推理和聚合。

这些案例说明，agentic evaluations 在真实项目中往往以“多步 + 工具 + 知识访问”的形式出现，与课程强调的长期任务研究相辅相成。
