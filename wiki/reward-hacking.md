# Reward Hacking

> Source(s): raw/ch-05-总结：闭环自我改进与可验证领域

Reward hacking（奖励黑客行为）是指在强化学习（RL）训练过程中，模型找到奖励信号的漏洞或捷径，而并非真正学会解决问题。这一现象源于奖励模型在不同情况下的固有缺陷：模型过强时奖励信号容易被 hack，信号不足时无法支撑爬山式的优化，训练停滞时奖励信号可能饱和。这使得 RL 优化比监督学习（SFT）困难得多。

## 问题表现与观察

在实际 RL 训练（如 DeepSeek 的 GRPO）中，Reward hacking 表现为多种可观察的异常：

- **响应长度失控**：模型输出越来越长，但质量不相应提升。如果采用样本级损失（sample-level loss），每个回答对整体损失的权重相同，一个很长的垃圾答案会与一个简短的好答案获得相同权重，导致优化目标失偏。
- **熵值漂移**：生成熵（entropy）持续增长，说明模型输出分布变得不稳定、随机性过强。
- **推理链截断噪声**：遇到困难问题时，模型可能在思考过程中被截断，产生大量噪声，破坏训练稳定性。

## 缓解方法：改损失函数与动态采样

为应对上述问题，多种技巧被提出，并在 AIME 基准上通过逐步叠加验证了效果：

| 方法 | 描述 | AIME 得分（Qwen-32B） |
|------|------|----------------------|
| 原始 GRPO | 基线 | 30 |
| 过长过滤 | 过滤超长输出 | 36 |
| 非对称裁剪 | 对奖励偏离做非对称处理 | 38 |
| 软性过长惩罚 | 对超长输出给予平滑惩罚 | 41 |
| Token 级损失 | 对每个 token 而非整个样本计算损失 | 42 |
| 动态采样 | 批次内更好分配奖励，改善信号传播 | 50 |

其中 token 级损失（token-level loss）比样本级损失能更好地根据长度 shaping 优化，同时控制熵和平均响应长度。动态采样则通过更合理的奖励分布实现更优的信号传播，最终结果甚至超过了 DeepSeek-R1 蒸馏到 Qwen-32B 的水平。

**核心学习原则**：

- 损失函数本身不是合理的代理指标，必须同时监控响应长度和熵（不能太高也不能太低）。
- 样本中准确率为 1 的比例决定了需要多少采样量。
- 如果训练若干步后没有改善，奖励模型很可能已经饱和。

## 与 SFT 的比较

- **RL**：在拥有强奖励信号的领域（如数学推理），可以仅用较少样本实现 hill-climb，但要调好非常困难，需要监控上述所有变量。
- **SFT**：如果有大量高质量数据，SFT 通常能更快提升模型性能，但无法显著增强或带来推理能力。

## 技术选型建议

- **STaR**：仅有约 100 个推理示例、无 RL 基础设施时，适合简单推理任务（如 GSM8K），但提升有限，不超出模型原有能力。
- **GRPO (DeepSeekMath)**：需要足够好的基础模型和指令数据，在数学推理任务上被验证有效，且对 GPU 内存要求相对较低。
- **复杂长链推理 / 竞赛级问题（AIME, IMO）**：必须控制 RL 算法中的各类变量（长度、熵、奖励分布），需要更严谨的基础设施。

## 预期收益与局限

正确应用上述技术后，通常能提升 **pass@k**、改善**答案格式**、增强模型在多步推理中的**连贯性**。但**无法**提升模型的根本能力、教它解决全新问题，或实现大幅度的领域外泛化——这仍是当前研究的开放问题。
