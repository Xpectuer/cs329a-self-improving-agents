# Inference Scaling（推理阶段扩展）

> Source(s): raw/ch-06-语言模型的训练流程：预训练、微调与对齐; raw/ch-01-引言：从预训练到推理时计算扩展; raw/ch-05-工程范式转变：将更多算力投入推理阶段; raw/ch-07-不可验证领域中的选择方法：多数投票与模型排序器的局限; raw/ch-01-引言：训练时扩展（Train-Time Scaling）; raw/ch-03-未来研究方向概览

语言模型的能力提升一直依赖训练侧的扩展，包括 **预训练（pre-training）**、**微调（fine-tuning）** 和 **对齐（alignment）**。但在最近约一年半的时间里，**推理阶段（inference / test-time）的计算扩展** 也成为一个新前沿，为模型能力提升带来了全新的研究方向。

值得注意的是，在课程脉络中，推理时扩展并非孤立出现。正如新引入的讲座引言所述：

> Welcome, everyone, to the sixth lecture for CS320A. We'll today cover train time scaling or scaling RL. So far, we have gone through several topics related to test time scaling, feedback using tools and code, and then also robust verification. Today, we will see how we can close the loop to improve the models even further.

这揭示了**推理时扩展**与**训练时扩展（Train-Time Scaling）**之间的互补关系：在系统学习了测试时计算扩展、工具反馈、稳健验证之后，训练时扩展（特别是强化学习）成为进一步闭环提升模型能力的下一步。

## 训练侧的核心流程

### 预训练（Pre-training）

预训练是任何语言模型训练的第一步，也是最基础的步骤。模型被训练用于预测下一 token，输入数据来自互联网、书籍等各种文本。经过预训练的模型只是从统计意义上了解了世界状态，并不真正“知道”事实，也没有遵循指令的能力。

历史上，预训练也是三个发展阶段中计算投入最大的环节，往往需要耗费数月时间，使用大量 GPU 集群进行训练，处理的数据规模可达数万亿 token。

## 训练时扩展 vs. 推理时扩展

推理时计算扩展主要是指在**推理或测试阶段**投入额外计算（如重复采样、搜索、验证）来提升模型表现，而无需修改参数。与之相对，**训练时扩展（scaling RL）**则强调在训练阶段通过强化学习等方式进一步优化模型。两者在计算投入的时机上存在根本差异，但在追求模型能力上限的目标上殊途同归。

从上述讲座引言也可以看到，课程设计本身将其视为一个递进链条：先掌握测试时的各种技巧，再通过训练时扩展“闭环”改进模型。推理时扩展并非替代训练时扩展，而是与之互补，共同构成完整的扩展策略空间。

## 不可验证领域中的选择：多数投票与模型排序器的局限

在可以通过外部工具验证答案的领域（如数学、代码）中，重复采样配合验证器（verifier）可以显著提升正确率。然而，对于许多**没有可靠验证器**的领域，情况则完全不同。观察发现，在这些领域中，**多数投票（majority vote）** 和基于模型的排序器（model-based ranker）与模型真实覆盖能力之间存在巨大差距。

具体而言，若以“完美选择器”（即假设存在一个完美的验证器）所能达到的覆盖率为上限，多数投票在采样数超过 10～50 个后便趋于平台期，两者之间的差距在更难的数据集（如 MATH vs. GSM8K）上更为明显。即使改用奖励模型（reward model）来为每个回答打分并选取最高分，这一差距依然显著。这种“模型能生成大量正确响应，却无法有效筛选出来”的现象被称为**生成-验证差距（generation-verification gap）**。

造成多数投票失效的一个关键原因是：对于最难的那部分问题，正确的答案在 1,000 或 10,000 个样本中可能仅出现一次、两次或三次。少数但正确的回答被大量错误答案淹没，多数投票自然无法识别它们。而在较简单的 GSM8K 问题上，正确答案出现的频率相对较高，多数投票尚能奏效；但即便是简单问题，最难的子集也面临同样低频率的挑战，这使得从验证角度出发如何找到正确回答变得极为困难。

这一观察也引发了关于如何进一步改进测试时计算的讨论。除了单纯增加重复采样之外，还存在**自我学习（self-study）**、**搜索（search）** 与**工具使用（tool use）** 等策略，它们可以在不可验证领域中帮助模型更好地探索与收敛。此外，验证器的质量对整体系统上限起着决定性作用；也有研究尝试将知识图谱、检索增强（RAG）等外部知识与排序方法结合，在准确性与效率之间取得平衡。

## 未来研究方向

从课程的整体脉络来看，推理时扩展的探索已经超出了单纯的采样与投票范畴，逐渐与更广泛的智能体（agent）工作流、训练时扩展以及数据策略交织在一起。课程在回顾了测试时扩展、训练时扩展、进化策略、端到端智能体工作流等主题后，指出了若干未来研究的关键方向，这些方向都直接或间接地影响着推理时扩展的下一步发展。

### 跨域泛化与推理链多样性

目前测试时扩展和训练时扩展的自改进循环大多局限于数学、代码等窄域。如何在更广泛的领域实现泛化，并让模型生成的**推理链（reasoning chains）**保持足够的多样性，从而持续驱动自改进循环，是当前重要的开放问题。推理时扩展在窄域中依赖可验证的奖励信号，而跨域后如何获得有效反馈、如何设计多样性采样策略，都需要新的方法。

### 稳健验证与元验证

构建自改进循环的核心依然是验证。除了针对最终答案的验证器，未来的重要方向是**稳健验证（robust verification）**和**元验证（meta-verification）**——即验证进入推理链的输入、中间步骤和假设是否合理。这不仅能提升推理时扩展的选择质量，也有助于缩小生成-验证差距。

### 突破数据障碍

训练时扩展中，用于训练模型的提示（prompts）选择往往非常静态，且依赖人工挑选。如何让自改进循环自主选择最合适的数据来驱动自身进步，是打破数据瓶颈的关键。推理时扩展同样受益于更智能的数据利用：在测试阶段投入的计算资源应当被导向最有价值的样本和路径，而不是均匀分配。

### 智能效率

除了追求更高的智能水平，如何提升“每个单位的智能效率”（intelligence per compute / per data / per interaction）也成为重要议题。在推理时扩展中，这意味着在采样、验证、搜索之间寻找更优的分配策略，避免在简单问题上过度计算，而将资源集中在能带来实际增益的困难样本上。

此外，课程还强调了智能体（agent）的视角：推理时扩展不仅是单个模型的采样，而是在一个可能包含多个 LLM 调用、工具调用、搜索算法和验证器的**智能体工作流**中，为了实现目标而进行规划、多步推理和自我纠正。这种工作流中的推理时计算分配，正在成为工程实践和研究共同关注的重点。

## 总结

推理时计算扩展为突破训练侧瓶颈提供了新路径，但在不可验证领域，验证能力成为关键制约。缩小生成-验证差距，或者发展更强的选择器，是未来研究的重要方向。与此同时，训练时扩展（如 scaling RL）则从另一个维度提升了模型的固有“生成”能力，两者结合可能才是通往更强语言模型的完整路径。未来，跨域泛化、稳健验证、数据障碍突破和智能效率将是这个领域持续演进的四个支点。
