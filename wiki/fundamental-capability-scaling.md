# Fundamental Capability Scaling

> Source(s): raw/ch-05-总结：闭环自我改进与可验证领域

## RL 优化中的实际问题

在基于 GRPO 等强化学习算法进行推理训练时，损失函数的设计需要超越简单的样本级（sample-level）损失。原始材料指出，如果对每个问题和答案对计算样本级损失，那么长答案和短答案会被赋予相同的权重，长段垃圾输出会干扰训练。因此需要引入 **token 级损失**（token-level loss）或长度惩罚，以更好塑造训练信号。

同时需要控制两个关键指标：

- **熵**（entropy）：不能过高也不能过低，否则训练不稳定。
- **响应长度**（response length）：如果模型输出长度爆炸，需要加以约束。

此外，模型在遇到难题时推理链往往被截断，这些被截断的链会产生噪声。可以通过在 token 上加入渐进惩罚（gradual penalty）来稳定训练，而不是简单地扩大上下文长度。

动态采样（dynamic sampling）也能改善批内奖励分布，提升信号传播效率。

## AIME 基准上的效果提升

以 GRPO 在 AIME 基准上的表现为例，逐步叠加不同技巧后得分变化如下：

- 过滤过长的输出：30 → 36
- 非对称裁剪（asymmetric clipping）：→ 38
- 柔性过长惩罚（soft overlong punishment）：→ 41
- token 级损失：→ 42
- 动态采样：→ 50

这一结果甚至优于 DeepSeek-R1 蒸馏到 Qwen-32B 的效果。这说明通过细致的 RL 工程调优，可以在基座模型上自行攀爬（hill climb）出更强的推理能力。

## SFT vs RL

在强奖励信号的领域内，RL 可以用更少的样本进行“攀爬”，但调优成本很高。如果拥有大量高质量数据，**监督微调（SFT）** 可以更快提升模型性能，但不会带来推理能力的质变或额外增强。

## STaR、GRPO 与 DAPO 的适用场景

三种技术各有定位：

- **STaR**：适合少量示例（如 100 条推理样例）且没有 RL 基础设施时，快速让模型开始推理。在 GSM8K 这类简单任务上会有一定提升，但仍局限于模型已有能力范围。
- **GRPO**（DeepSeekMath 中应用）：需要较好的基座模型和指令数据，但算法较强，可在 GPU 资源有限时工作，适合标准数学推理任务。
- **DAPO 等进阶技术**：当推理链变长（通常对应更难题）且需追求最优性能时，需要控制 RL 算法与基础设施中的各种变量，对 AIME、IMO 等竞赛级题目非常有用。

## 能力的边界

所有三种技术都会：

- 随着计算量增加提升 **pass@k**（多数为 K 性能）；
- 改善**答案格式**；
- 增强多步推理的**连贯性**。

但是，**这些技术都不能提升模型的根本能力（fundamental capability），也无法教会模型解决新问题或进行大幅度的跨领域泛化**。原始材料最后追问：到底需要什么条件，才能让这一最后的能力开始改善？
