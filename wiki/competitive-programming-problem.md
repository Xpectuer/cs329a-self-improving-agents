# 竞赛编程问题

> Source(s): raw/ch-02-AlphaCode 问题背景与定义

**竞赛编程问题**（competitive programming problem）是编程智能体任务中更为复杂的一类。与常见的代码补全不同，竞赛编程问题给出一段**问题描述**以及若干**输入/输出样例**，这些样例构成一个明确契约：对于给定的输入集合，程序必须产生对应的输出集合。模型的任务不是补全一行代码，而是先理解题意，再端到端地生成完整的解法。

## 与代码补全的对比

传统编码智能体（coding agent）本质上是一种自动补全：给定当前代码行，模型补全后续内容。竞赛编程问题则要求模型一次性生成大段代码，解决真实、完整的编程问题。这种端到端求解方式远比单行补全困难：

- **单行补全**交互简单、成功率高（如 Copilot 等工具）；
- **端到端求解**需要模型自行完成问题理解、算法设计、代码生成全部环节。

竞赛编程问题也不同于 HumanEval 这类小规模评测任务。HumanEval 中的问题往往只是补全一个函数，或给出非常明确的指令，模型无需深入理解问题域。竞赛编程问题则包含：

- **更长的题目描述**；
- **更长的解法代码**；
- **先行理解题目**：需要从描述中判断正确的解法思路，而不是简单把指令翻译成代码。

AlphaCode 论文是这一领域的代表性工作。该模型在约四年前发布时，在 10 场编程竞赛中超过 54% 的人类参赛者，首次展示了 AI 能够超越狭窄任务、端到端解决泛化问题的能力。

## 解决流程中的关键环节

在 AlphaCode 的原始方案中，竞赛编程问题的求解流程包括以下阶段：

1. **训练模型**：在早期没有大型语言模型时，AlphaCode 使用 GitHub 数据与竞赛编程（code contests）数据（大量竞赛题目与解答）进行预训练和微调。
2. **大规模重复采样**：模型训练完成后，对每个问题采样大量候选解决方案，规模远大于一般的重复采样设置。
3. **筛选候选方案**：不是对模型输出的所有方案直接运行测试，而是先利用一些技巧选择“值得测试”的候选子集，再进入执行与评估阶段。这一选择-验证过程与生成-验证差距直接相关。

这一流程说明，竞赛编程问题不仅考验模型的生成能力，也对后续的筛选、验证和推理扩展提出了更高要求。
