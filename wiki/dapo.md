# DAPO（长链推理的强化学习稳定化）

> Source(s): raw/ch-04-论文三：DAPO（长链推理的强化学习稳定化）、raw/ch-05-总结：闭环自我改进与可验证领域

DAPO 是本章讨论的第三篇论文，核心关注在长链推理场景下如何稳定强化学习（Reinforcement Learning）算法。与监督学习不同，强化学习的实现细节往往难以正确调优，而这些“小修复”在算法扩展到更大规模时极为关键。

## 背景：AIME 基准

AIME（American Invitational Mathematics Examination）是一个数学推理基准，题目比早期的 MATH 基准更复杂。由于 MATH 已被多数模型训练覆盖（饱和与污染），研究者转向 AIME 2024 和 AIME 2025 作为新的评估基准。这也是作业 1 中使用的基准。

在该基准上的表现对比：

- **GPT-3.5**（1750 亿参数）：约 5% 准确率
- **DeepSeekMath**（7B 模型，使用 train time scaling）：51.7% 准确率，配合额外技巧可达 60%
- **Qwen-32B 应用 DAPO**：约 50% 准确率

这些结果表明，即使模型参数规模较小，通过训练时间扩展（train time scaling）也能在推理基准上取得很高的性能，这与“只靠增大参数规模提升能力”的传统认知形成对比。

## 核心洞见

- **自我改进**：在预训练之后，如果模型能够从自身输出中学习，并通过巧妙过滤来挑选有效样本，模型能力可以进一步提升。
- **计算替代参数**：投入在模型自身输出上的训练计算量，可以在一定程度上替代模型参数规模的增加。
- **实现细节至关重要**：强化学习与监督学习不同，在算法扩展时，小修复（如采样策略、奖励设计、过滤逻辑）的影响可能极其显著，必须仔细处理。
- **损失函数不是充分代理**：在 RL 中学习时，损失函数本身不足以反映训练质量，必须同时监控响应长度、熵（不过高也不过低）以及全对样本（准确率为 1）的百分比。后者可以指示需要多少采样，三者都是 RL 学习中的重要原则。

## 关键技术改进

DAPO 在 GRPO 基础上引入了多项针对长链推理的稳定化技术，这些技术共同解决了熵崩溃、长度失控和截断噪声等问题。

### 1. Token 级损失（Token-level Loss）

在标准 GRPO 中，每个样本（question-answer pair）作为一个整体计算损失，即样本级损失。这导致一个长而混乱的答案与一个短而正确的答案在损失函数中拥有相同的权重。本质上，样本级损失会让每个回答被“全局”计数，无法对长度进行有效调节。

DAPO 提出将损失改为 **token 级**，即对序列中的每个 token 单独计算损失并加权。这样做本质上是引入了一种随长度变化的形状调整——更长的输出会积累更多的 loss 贡献，从而天然形成对长度的调节。实验表明，token 级损失能够同时稳定**熵**和**平均响应长度**：如果没有这种损失，随着模型不断生成长推理链，熵会持续增长、响应长度也会失控膨胀。因此，通过 token 级损失施加长度惩罚，可以更好地塑造模型行为。

### 2. 渐进式 Token 惩罚（Gradual Token Penalty for Truncated Chains）

在训练过程中，模型会遇到难题并持续生成推理链，最终因达到上下文截断限制而被强行截断。这些被截断的推理链会产生大量噪声，破坏训练稳定性。

DAPO 的做法是对截断发生在末尾的 token 施加**渐进式惩罚**：越接近截断点的 token，其损失惩罚越强。另一种常见的处理方式是在 RL 循环中直接扩大上下文长度，但 DAPO 选择用惩罚函数平滑地处理截断带来的噪声，而不是生硬地丢弃或同等对待所有被截断的样本，从而让训练过程保持稳定。这样既避免了因截断引入的噪声，又不需要额外增加上下文长度带来的计算开销。

### 3. 动态采样（Dynamic Sampling）

DAPO 还优化了批次内的奖励分布，通过动态采样让奖励信号在批次内更均匀地传播——即对批次中的样本做更好的奖励分配，从而改善梯度信号的质量，进一步提升最终性能。这种“更好的信号传播”是最终突破到更高准确率的关键一环。

## 消融实验与性能提升

在 Qwen-32B 模型上，从基础 GRPO 出发，各项改进带来的 AIME 准确率提升如下：

| 方法 | AIME 准确率 |
|---|---|
| 基础 GRPO + overlong filtering | 30 → 36 |
| + 非对称裁剪（asymmetric clipping） | 38 |
| + 软超长惩罚（soft overlong punishment） | 41 |
| + token 级损失（token-level loss） | 42 |
| + 动态采样（dynamic sampling） | 50 |

最终达到的 **50%** 准确率甚至超过了 DeepSeek-R1 蒸馏到 Qwen-32B 的效果，说明通过仔细控制 RL 细节，可以在不依赖更大模型蒸馏的情况下自行“爬山”（hill climb）到强性能。

## 三种训练范式

1. **预训练（Pre-training）**：在互联网数据上训练模型，已在第一讲中介绍。
2. **微调（Fine-tuning）**：通过人类反馈（RLHF）或 AI 反馈（RLAIF）在偏好数据上微调，得到聊天机器人等应用。
3. **测试时间扩展（Test-time scaling）**：推理阶段的技巧，如多数投票、采样并组合输出等（见作业 1）。这些属于推理侧的方法。

如果将测试时间扩展后得到的模型输出作为过滤后的数据，再用来进一步微调模型，这个过程大致就是**训练时间扩展（train time scaling）**。简而言之：

> 生成模型输出 → 过滤 → 反馈训练 → 改进模型 → 再生成……

这一循环是理解训练时间扩展的基础。

## 与 o1 的关联

o1 在 AIME 上的结果表明：增加测试时间计算（inference compute）可以提升 pass@1 准确率；同时，增加训练时间计算也能提升同一指标。两者结合形成了一个循环：生成输出、反馈、再训练，从而在基准上持续改进。数学领域具有**可验证性**，这使得模型能够明确判断输出是否正确，从而支撑该循环的有效性。

## RL 与 SFT 的取舍

从 DAPO 的经验也可以回答常见的“监督微调（SFT）还是强化学习（RL）”问题。在有强奖励信号的领域（如数学），RL 可以用更少的标注示例实现自举式爬山，但需要大量的工程调优；而 SFT 如果拥有大量高质量数据，通常能更快地提升模型性能，但不会从根本上带来新的推理能力或显著增强推理深度。

同时，RL 的优化难度更高：如果响应长度在模型输出中爆炸，需要控制损失；如果熵失控，也需要干预；如果经过一定步骤后没有改进，说明奖励模型可能已经饱和。这些都是 RL 训练中必须警惕的挑战。

## RL 训练中的监控指标与挑战

DAPO 的经验表明，在 RL 训练中必须关注三个关键指标：

- **响应长度（response length）**：如果模型输出的响应长度不断膨胀，说明模型可能依赖冗长甚至无效的推理链，需要在损失上加以控制。
- **熵（entropy）**：熵既不能太低（可能导致模式坍缩、缺乏探索），也不能太高（可能导致输出不稳定、随机性过强）。token 级损失等机制有助于将熵维持在一个合理区间。
- **全对样本占比（% of samples with accuracy = 1）**：这个比例可以告诉研究者当前需要多少采样，以及奖励信号是否还有区分度。如果经过很多步仍无提升，则可能意味着奖励模型已饱和。

这些指标相互关联，单看损失函数不足以诊断训练状态。

## 技术选择与改进边界

根据 DAPO 的总结，不同技术有各自的适用场景：

- **STaR**：如果你只有少量推理示例（如 100 个）且没有 RL 基础设施，STaR 是让模型开始学习推理的较好起点。对于 GSM8K 这类简单推理任务，会有合理改善，但不会超出模型原有能力太多。
- **GRPO（如 DeepSeekMath）**：需要足够好的基础模型，并用优质指令数据预热。在有限 GPU 内存下也能有效运行，适合标准数学推理任务。
- **DAPO 风格算法**：当推理链很长（通常对应更难的题目）且追求 SOTA 性能时，必须在 RL 算法和基础设施中控制所有上述变量。这对于 AIME、IMO 等竞赛级问题非常有用。

期望这些技术带来的普遍改进包括：提升多数投票（pass@k）性能、改善答案格式、增强多步推理的连贯性。但需要注意，这些技术目前并不会从根本上提升模型解决全新问题的能力，也不会显著扩展到领域外泛化——这是未来需要继续探索的方向。
