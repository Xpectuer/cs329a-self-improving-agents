# 第 5 课学习记录：工具与代码反馈

**日期**：2026-09-01（课程制作中，quiz 待用户完成）
**主题**：工具与代码反馈（Tool Calling / Execution Feedback / Agent Search）

## 课程定位

本课从「反馈获取方式」角度收拢前四课：第 2 课验证器是**静态/判别式**反馈，第 3 课测试时扩展是**采样**，第 4 课训练时扩展是**把信号固化**——第 5 课的核心是：**模型通过调用工具主动执行动作，从环境中获得动态、正确性导向的反馈**，再与搜索（LATS）或 RL（RLEF）结合，形成「执行—反馈—改进」的真正闭环。

## 关键知识

- **工具调用（tool calling）**：模型不只是一次性生成，而是可以调用代码解释器、搜索引擎、外部 API 等工具，获取环境反馈、执行多步任务。这是从「纯生成模型」到「智能体」的枢纽。
- **代码反馈（execution feedback）**：运行生成的代码 / 跑单元测试，得到「是否运行成功 / 是否通过」的**执行信号**——比静态文本评估强得多，因为它验证的是行为而非表面。
- **可验证领域**：数学（形式化证明）、编程（单元测试）、语言转换（输入/输出等价性，如 AI-as-a-Compiler / KernelBench）——验证机制比生成更简单时，反馈可大规模自动化。KernelBench 观察到：随采样增加，CUDA 代码覆盖率**线性提升**（有完美验证器）。
- **RLEF**：把「执行反馈」用作强化学习信号，引导代码 LLM 学习「能跑、测试通过」的代码——执行反馈不只做筛选，还做**学习信号**。
- **Agent Search**：在智能体的动作/轨迹空间搜索（对应 deep research 式任务），代码模型搜索（AlphaCode 大量采样）是它的「简单版」。
- **LATS**：把 MCTS 引入 LLM 推理路径的测试时搜索——选择/扩展/评估/模拟/反向传播/反思六阶段，评估 = LLM 打分 + 自洽性分数，反思把成败经验带回。无需微调，HotPotQA/WebShop 接近人类专家。

## 与前课衔接

- 生成-验证差距（第 2 课）：工具执行给了「验证」一个**动态来源**——不再是判断答案，而是让程序跑起来看结果。
- 测试时扩展（第 3 课）：LATS 是「采样 + 搜索」全用上，且是模块化可移植的。
- 训练时扩展（第 4 课）：RLEF 用执行反馈做 RL 奖励，与 DAPO 同在可验证领域闭环。

## 课后追加：共享资源 insight（2026-09-01）

用户追问「LATS 多条分支 rollout 涉及共享资源（如每次只能动一台设备）如何解决？」——展示出对**真实世界约束**的迁移敏感度，是论文演示环境之外的盲区提问。

- 核心结论：原版 LATS **未处理**共享资源互斥——它的评测环境（WebShop/HotPotQA/迷宫/HumanEval）全部可重置/无副作用，天然规避冲突。「并行执行」只是 LLM 文本采样并行，物理执行在无克隆能力的环境必须串行。
- 辨析升级：LATS 的地基假设从「行动可逆」（wiki 课堂讨论原话）深化为「**环境可回放**」（可重置/无副作用）——比可逆更强；树分岔 = 回到父状态重放。
