上一课我们说验证是闭环的一环。这一课要直面一个扎心的事实：模型「会做」但未必「会判」——这就是生成-验证差距，它是测试时扩展与训练时扩展共同的瓶颈。

1. 差距是什么

生成-验证差距（generation-verification gap）：模型的生成能力强，验证能力弱。当没有可靠验证器时，从一大堆自己生成的候选里选出正确解，远比生成它们更难。（wiki 页）

两条实证证据：

  • 多数投票会饱和：采样到 10~50 个答案后，多数投票性能就趋于平稳；而假设存在完美验证器，性能上限远高于它——且在更难的任务（MATH vs GSM8K）上差距更大。
  • 10@k vs pass@k：在 1M 采样下，只能提交 10 个解时成功率约 30%（10@M），全部提交可超 40%（pass@M）——筛选/聚类阶段是瓶颈；聚类能显著回补 10@k。

2. 为什么它是瓶颈

验证器是闭环的枢纽，同一个验证器站在两个位置上：

测试时：生成 → 验证器筛选 → 提交（best-of-n、10@k）
训练时：生成 → 验证器打分 → 奖励 → 更新权重（STaR、RLVR）

没有可信验证：测试时不知道选哪个（只能退回多数投票），训练时不知道奖励什么（退不回来——没有奖励信号就谈不上学习）。验证器的质量决定了整个自进化闭环的天花板。（wiki 页）

3. 四类验证器怎么选

类型判什么一句话定位
符号/规则数学答案、单元测试、输出等价可靠自动，但只限可验证领域
ORM（结果奖励模型）最终答案整体打分标注便宜，但「只知道对错，不知错哪」
PRM（过程奖励模型）推理每一步打分能定位错步，但步骤标注贵
LLM-as-a-Judge开放式输出质量灵活可靠存疑，适合开放任务

ORM vs PRM 的取舍：ORM 只要答案对错就能训，适合整体筛选（best-of-n）；PRM 是过程监督，能更早定位错误、给训练提供细粒度信号，但需要步骤级标注——PRM800K 就用了约 80 万个步骤的人类标注。

Math-Shepherd 的招：不人工标步骤，而把「步骤质量」定义为从该步骤出发最终到达正确解的可能性——从每步继续采样 N 条轨迹看正确比例（硬估计：有一条对 → 1；软估计：按频率），再用这个 PRM 既做测试时选择也做训练时强化，无人工标注就超过了 SC / ORM / PRM800K 基线。（PRM · Math-Shepherd）

4. 为什么数学、编程、语言转换最成熟

验证机制必须比生成任务本身更简单，才能大规模自动筛选。（可验证领域）

形式化证明、单元测试/执行反馈、输入输出等价性都满足这一点——于是「生成→验证→筛选→更新」闭环可靠运转。数学上的结果：GPT-3.5 在 AIME 约 5%，DeepSeekMath-7B 靠训练时扩展冲到 51.7%+，基座不大却大幅反超。可验证领域，是自进化最肥沃的土壤。

5. 练习：五道题，凭记忆作答

  1. Q1. 生成-验证差距说的是？

    模型能生成大量正确候选（pass@k 很高），但可靠地从候选中挑出正确解难得多——生成强、验证弱。

  2. Q2. 验证器在闭环中的两个位置是？

    测试时做「选」（best-of-n、10@k 筛选）；训练时做「教」（打分给奖励信号）。生成/更新是别的环节。

  3. Q3. 想定位推理错在哪一步，用哪种？

    PRM 对推理每一步打分（过程监督），能早定位错误；ORM 只对最终结果打分。

  4. Q4. 数学编程自进化最成熟，主因是？

    验证机制比生成任务更简单（形式化证明/单测/输出等价），可靠信号支撑了大规模筛选与训练。

  5. Q5. Math-Shepherd 如何替代人工步骤标注？

    把每次 rollout 到完成的正确性作为「该步骤质量」的估计（硬/软估计），自动打标签训 PRM。
