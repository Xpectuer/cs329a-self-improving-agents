第 1 课 · 自进化是什么

第 1 课 / 共 9 课 · 约 6 分钟 · 配套参考：自进化框架速查卡 · 词汇表

你已经把 CS329A 的 9 讲转录整理成了 59+ 个知识页——它们像散落的拼图。这节课给你两块"地图入口"：闭环（课程怎么描述自进化）和四问题（综述怎么拆分自进化），最后用三标准教你怎么判断一个系统到底算不算真自进化。

1. 课程定义：一个闭环

CS329A 第 2 讲把 self-improving agent 定义为：能通过验证器、奖励、强化学习和搜索的闭环，自主提升自身能力的智能体。闭环四步：

生成 → 验证 → 学习 → 搜索

模型先生成候选解 → 验证器给每个候选打分 → 反馈变成奖励信号 → 强化学习更新策略 → 推理时搜索探索更优候选。

这个循环不断重复，模型就持续变好——这就是全课 9 讲穿起来的主线。（wiki 页 · 词汇表称其抽象版为「生成→验证→反馈→更新」）

2. 综述框架：四个问题

领域综述（Gao et al. 2025）把"自进化"拆成四个正交问题——对任意 agent 系统，回答这四个问题就能给它贴一张完整标签：

问题答案维度一例
What 改什么模型参数 / 上下文（提示、记忆）/ 工具集 / 架构拓扑STaR 改模型参数
When 何时改测试内（intra-test-time，靠 ICL）/ 测试间（inter-test-time，靠 SFT 或 RL）best-of-n 是测试内
How 怎么改奖励驱动 / 模仿演示 / 种群演化GRPO 是奖励驱动
Where 属于哪类任务通用 / 领域专用（编码、GUI、金融、医学、教育）AlphaCode 是编码

形式上把「改什么」写成一个函数：Π′= f(Π, 轨迹, 反馈)，即系统在任务轨迹与反馈驱动下变到新状态（Gao et al. §2.1）。

3. 三标准：算不算"真"自进化

很多系统都"会改进"，但不是所有都算自进化。综述给了操作性定义：

自进化 agent 是基于自身轨迹或反馈信号，修改其内部参数、上下文状态、工具集或架构拓扑，且明确以提升未来性能为目标的 agent。

三条纳入标准（缺一不可）：

#标准一句话
(i)经验驱动更新来自自身轨迹/自生成数据/环境反馈，针对能力边界
(ii)持久效果产生持久、改变策略的作用，不是一次性行为
(iii)自主探索有自主探索或自发学习的机制（自我反思、主动修改）

现实中大部分系统落在「前自进化（proto-evolution）」到「强自进化」的光谱上，综述不设硬边界——但标准 (i)(ii)(iii) 是判断的口径。

4. 练习：五道题，凭记忆作答

先别翻 wiki。答完立即反馈。（选项均为 7 字，无格式暗示）

  1. Q1. CS329A 第 2 讲给出的自进化闭环顺序是？

    课程主线的闭环：生成候选解 → 验证器打分 → 反馈转奖励，RL 更新策略 → 推理时搜索更优候选，周而复始。

  2. Q2. 闭环中验证器（verifier）负责什么？

    验证器是「把生成了什么变成值多少」的那一环：对候选打分或判定正误；生成、更新、搜索是另外三环。

  3. Q3. STaR 用自生成的正确推理链迭代微调权重，演化位点是？

    STaR 反复「生成推理 → 筛出正确的 → 用它微调模型」，改的是模型权重，所以 What = 模型参数。

  4. Q4. LATS 在单个任务内做树搜索，靠 LLM 裁判反馈指导后续节点，不改权重。演化发生在？

    搜索 → 反思 → 反馈 → 改策略，全部发生在任务执行中，优化的是当前这一题，属于 intra-test-time（测试内时间演化）。

  5. Q5. 某系统只用人类标注的静态数据微调，不依据自身轨迹。它缺少哪条标准？

    标准 (i) 要求更新由自身轨迹、自生成数据或环境反馈驱动；只用人工静态数据、不依据自身轨迹，恰是缺少经验驱动。
